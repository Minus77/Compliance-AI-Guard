# 安全与风险

[English](../security-and-risk.md) · **简体中文**

信任边界、AI 风险登记册以及每项风险的缓解控制。这些控制对应当前实现的服务
及其回归测试。

## 1. 信任边界

每个请求有三条关键边界：

| 边界 | 规则 | 执行位置 |
| --- | --- | --- |
| **客户端 → 检查服务** | 内容与声明都是不可信数据。身份、租户、策略作用域、严重度、路由与发布权限由服务端推导 | 会话或演示角色解析、租户校验、请求 Schema、保留字段拒绝、确定性策略 |
| **检查服务 → 模型** | 外部模型访问前完成注入扫描与标识符打码。只发送有边界的事实和服务端保存的安全输入 | 注入扫描、实体消解、按片段打码、数据类别路由、档案校验 |
| **模型候选 → 发布** | 模型输出不能设置处置或自行发布。完整候选必须通过 Schema 校验和输出策略检查 | 有界网关、输出完整缓冲、策略引擎、发布前审计 |

连接器响应和导入的规则文件属于第一条边界内的不可信输入。规则必须通过 Schema
校验，连接器记录必须按 id 与版本回读。响应里出现角色、路由、工具或批准名称，
不会因此获得对应权限。

## 2. AI 风险登记册

可能性与影响分别缩写为 L 和 I。

| # | 风险 | L | I | 控制 |
| --- | --- | --- | --- | --- |
| R1 | 模型幻觉 | 中 | 高 | 输出仅作候选；Schema 校验；确定性策略；S0/S1 证据要求 |
| R2 | 证据过期或跨版本 | 中 | 高 | 快照 id；当前版本检索；跨版本发布门禁 |
| R3 | 漏检不良事件信号 | 中 | 高 | CN-001 与 CN-002 安全模式；安全与医学复核；不自动提交法规报告 |
| R4 | 个人信息或健康信息泄露 | 中 | 高 | 模型访问前完成实体消解和按片段打码；CN-006/007 S1 与 CN-008 S0 |
| R5 | 提示词注入 | 高 | 高 | 模型访问前扫描；CN-005 S0 阻断；工具或路由篡改只记录、绝不执行 |
| R6 | 证据缺口或检索投毒 | 中 | 中 | 封闭世界检索；可用性校验；显式 `needs_info` 或复核；不静默放行 |
| R7 | 供应商中断、超时或格式异常 | 中 | 中 | 失败安全状态；有界重试；人工接管；不发布未检查文本 |
| R8 | 任务使用错误模型 | 低 | 中 | 已发布任务路由按能力、区域、数据类别和启用状态校验 |
| R9 | 外部事件重复 | 中 | 中 | 按 `(tenant_id, event_id)` 幂等；确定性记录；可见死信重放 |
| R10 | 队列过载 | 低 | 中 | 有界聚合指标；按严重度与 SLA 排序；降级案例仍创建工作 |
| R11 | 错误的模型策略发布 | 低 | 高 | 版本化草稿校验；仅管理员发布和回滚；写入审计 |
| R12 | 商业利益输送 | 高 | 高 | CN-003 检测贿赂或不当诱导，阻断发布并转合规与法务 |
| R13 | 审核人或角色错配 | 中 | 中 | 规则级所需角色与 SLA；每个角色生成复核任务；服务端权限检查 |
| R14 | 自动化偏见 | 中 | 高 | 推翻率下限告警；放弃信号；S0/S1 不可自我批准 |

| R16 | 审计篡改 | 低 | 高 | 只追加哈希链；校验端点；不存在清除路径 |
| R17 | 自我声明身份 | 中 | 高 | 服务端会话；演示角色请求头仅在 `DEMO_MODE` 下有效；受保护 API 检查权限 |

## 3. 输入、生成与输出

AI 请求经过三个阶段：

1. **输入** — 扫描注入，完成实体消解与打码，应用输入入口规则；处置为
   `blocked` 时在模型调用前停止。
2. **生成** — 建立有效期 15 分钟的服务端会话，绑定操作者、租户、检查原文
   哈希、规则版本、安全输入和允许约束。只有同一份已检查提示词可以生成。
3. **输出** — 完整缓冲候选，校验 Schema，再应用共享策略与输出作用域规则。
   只有总处置为 `allow` 且所有 finding 都允许发布时才可释放。

被阻断输出会撤回，模型正文不会出现在安全响应中。输出检查异常返回
`failed_safe` 或人工降级状态。任何失败路径都不会发布未检查文本。

生成回复可以提出事实和措辞，但不能设置严重度、最终处置、复核路由、批准或工具
权限。提示词、操作者、租户、会话有效期或规则版本发生变化时，生成授权随之
失效。

## 4. 打码的两个失败方向

打码不足会泄露标识符。打码过度会破坏叙述，并可能在安全规则读取文本前删除不良
事件词汇。两者都是发布门禁，下限均为 1.0。

- 只在识别出的实体片段替换姓名和标识符。
- 实体消解先于打码，使同一个人的别名得到同一个稳定 token。
- 身份合并不确定时转为 `needs_info`，系统不会静默合并两个可能的人。
- 打码召回率和源保真度分别度量。召回率满分不能补偿被删除的症状。
- token 到身份的映射属于受限运营数据，不进入模型请求和默认审计载荷。

## 5. 注入与模型边界防御

注入扫描先于模型访问。CN-005 为 S0、`blocked`，立即转安全或合规章件处理。
已知注入用例与提示词调优隔离，出现一次危险 `allow` 就会让发布报告失败。

内容可以尝试修改路由、调用工具、泄露提示词、改变处置或指定高权限角色。这些
字符串始终只是数据。服务端路由由受信任配置解析，模型输出与发布权限之间也没有
工具边。

在规则作用域要求时，打码和注入扫描也适用于输出。完整缓冲阻止候选在全部检查
完成前被部分发布。

## 6. 复核、签名与推翻

复核任务来自 finding 与所需角色。审核人可以同意、要求补充、阻断或升级，并
记录理由。S0 与 S1 不能自我批准。签名表现形式绑定被审核的内容版本；内容被
修改后，先前决定立即失效。

复核队列保留底层处置、finding、任务与审计事件。队列过滤只是改变某个视图的
呈现，不会删除证据。

监督需要同时观察两个方向：审核人是否信任工具并继续使用，以及工作是否被纠正
或放弃。误报和漏报都可以成为回归候选，但需要另一名人员确认后才能进入黄金集。

## 7. 数据完整性与审计

审计日志是只追加哈希链。每条记录包含前一哈希、规范化的安全载荷和摘要。
`GET /api/audit-trail/verify` 会指出第一个无法验证的位置。

默认审计记录包含：

- 操作者、租户、请求标识与时间。
- 入口、内容类型、策略与规则版本、安全内容哈希。
- 处置、严重度、finding 引用、复核路由与模型档案 id。
- 模型调用状态、时延、输出检查状态、撤回与失败类别。

默认不包含原文、完整模型输出、敏感实体值、token 与身份映射、系统提示或凭据。
审计内容访问与审计导出分别授权。

发布前审计是控制措施的一部分。审计事件写入失败时，发布操作失败。一次成功
发布若缺少对应审计事件，会同时破坏可追溯性与归属。

## 8. 凭据与连接器

模型凭据位于环境变量或被 gitignore 的密钥文件。档案保存引用与打码值。草稿
校验拒绝明文密钥和字面量供应商端点。已发布配置带版本。

可选内容源、安全信号接入与复核导出连接器各自是独立信任边界。它们声明能力、
数据类别、允许动作和健康状态。事件投递只是通知；服务端会按记录 id 与版本回读
权威来源。连接器失败不会把缺失证据或安全信号变成批准。

## 9. 范围与非声称事项

本仓库是医疗内容和 AI 对话控制的可运行参考。它不声称完成 GxP/CSV 确认、法规
批准、药物警戒验证，也不保证适合某个特定市场。仓库内数据全部为合成数据。

本地身份存储、JSON 持久化、mock 连接器和演示视图不构成生产验证包。实际部署
仍需独立的威胁模型、身份集成、留存设计、监控、访问复核、备份恢复方案和符合
适用要求的验证证据。
