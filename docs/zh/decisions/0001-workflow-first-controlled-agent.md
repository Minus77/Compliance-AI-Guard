# 1. Workflow-first 受控 Agent

[English](../../decisions/0001-workflow-first-controlled-agent.md) · **简体中文**

日期：2026-08-20

修订：2026-10-28

## 状态

已接受（Accepted）

## 背景

医疗内容检查与 AI 对话防护会影响患者安全、个人信息、证据准确性、专业复核和
发布权限。一次错误的 `allow` 可能让不安全表述离开组织。

自行选择工具、状态转换和最终发布结论的开放式 Agent，会让上述结果取决于提示词。
这种设计难以复现、检查、回放，也难以向必须签署决定的审核人解释。

产品现在提供两个入口：人工提交的内容检查与 AI 对话防护。两者需要同一套规则库、
finding Schema、复核队列和审计链。入口特有的控制不同，因此工作流还需要为内容、
输入、生成和输出明确作用域。

## 决策

控制流位于确定性的服务端代码与状态机中。规则、策略优先级、权限、证据可用性、
Schema 校验、人工复核与审计决定路由和发布。

模型只承担有界语义工作：读懂语言、抽取结构化字段、提出 finding、起草候选回复。
它不能设置最终处置、严重度、批准状态、复核路由、发布权限或工具权限。

内容检查、AI 输入与 AI 输出共享策略评估和 finding。规则作用域限制各入口适用的
规则。AI 路径增加服务端绑定的对话会话：

- 模型访问前检查输入。
- 生成只使用服务端保存的已检查提示词、操作者、租户、原文哈希、规则版本和
  有效期。
- 输出完整缓冲并在发布前检查。
- 提示词、操作者、租户或规则版本发生变化时，需要重新检查。

失败路径保持关闭。供应商失败、格式异常、打码失败、权限拒绝、证据缺失或审计
写入失败都不能变为批准。不安全输出继续撤回。`MANUAL_DEGRADED`、
`FAILED_RETRYABLE` 与 `FAILED_SAFE` 保持可见，不能转为 `ALLOWED`。

角色使用中的专业能力，例如作者、审核人、安全审核人、医学审核人、法务审核人、
审计人、架构师和管理员。规则要求角色集合，不绑定特定组织岗位。内容模型使用
通用类型和可选调用方元数据；外部记录 id 不参与策略判定。

## 后果

- 高风险路径能够保持、失败安全、移交人工，并可从不可变版本回放。
- 同一风险不会因为从内容检查或 AI 对话进入而获得不同含义。
- 审核人可以检查结果背后的确切规则、证据、原文片段、档案与策略版本。
- 新模型与供应商通过版本化网关接入，不会获得发布权限。
- 服务需要比不受约束的聊天调用更多工程；错误规则仍然需要修复规则，修改提示词
  不能替代。
- 模型仍能生成有用的候选，同时最终权限保持可归属、可测试和可回滚。
- 复核工作量与自动化偏见仍是运营约束。监督必须双向度量，不能假定成立。
